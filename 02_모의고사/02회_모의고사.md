## Q1. 문제 — 상품 진열 순서

`products`의 원소는 `[이름, 할인율, 재고]` 형식입니다. 상품을 아래 기준으로 정렬한 뒤, 이름만 담은 배열을 return 하세요.

1. 할인율이 높은 상품이 앞섭니다.
2. 할인율이 같으면 재고가 많은 상품이 앞섭니다.
3. 할인율과 재고가 같으면 이름 사전순으로 앞선 상품이 앞섭니다.

### 제한사항

- `1 ≤ len(products) ≤ 100,000`
- 이름은 영소문자로만 이루어진 길이 1 이상 20 이하의 문자열입니다.
- 할인율과 재고는 0 이상 `10^9` 이하의 정수입니다.

### 입출력 예

| products | result |
|---|---|
| `[["pen",10,3],["book",10,5],["apple",20,1]]` | `["apple","book","pen"]` |

### 명세 확인

- 입력 `products`의 내부 배열 순서를 바꾸어도 됩니다.
- 이름 비교는 영소문자 사전순 비교입니다. 자연수 번호 비교가 아닙니다.
- 할인율·재고가 모두 같은 서로 다른 상품도 존재할 수 있습니다.

### 연습용 채점 그룹

| 그룹 | 조건 | 의도 |
|---|---|---|
| 1 | 상품 수 100 이하 | 세 정렬 기준을 정확히 적용하는지 확인 |
| 2 | 이름·할인율·재고가 모두 섞임 | 동점 우선순위를 빠뜨리지 않는지 확인 |
| 3 | 상품 수 100,000 | 비교 함수의 비효율적 반복 구현 방지 |

## Q1. 정답

```python
def solution(products):
    products.sort(key=lambda product: (-product[1], -product[2], product[0]))
    return [name for name, _, _ in products]
```

## Q1. 해설

내림차순이 필요한 숫자 값에는 음수를 붙이고, 이름은 그대로 정렬 키에 넣습니다. Python의 정렬은 튜플의 앞 원소부터 차례대로 비교하므로 세 기준을 한 번에 처리할 수 있습니다.

- 시간복잡도: `O(N log N)`
- 핵심 반례: 할인율과 재고가 모두 같은 `[["z",10,1],["a",10,1]]`의 결과는 `['a', 'z']`입니다.

## Q2. 문제 — 점검 구간 최대 매출

일 매출 배열 `sales`와 여러 질의 `queries`가 주어집니다. `queries`의 `[left, right]`는 1번 인덱스 기준으로 `left`일부터 `right`일까지를 뜻합니다.

각 질의 구간 안에서 골라야 하는 **비어 있지 않은 연속 부분배열**의 매출 합 최댓값을 순서대로 return 하세요.

### 제한사항

- `1 ≤ len(sales), len(queries) ≤ 100,000`
- `-10^6 ≤ sales[i] ≤ 10^6`
- `1 ≤ left ≤ right ≤ len(sales)`

### 입출력 예

| sales | queries | result |
|---|---|---|
| `[-2,3,-1,4,-5]` | `[[1,5],[2,4]]` | `[6,6]` |

첫 번째 질의의 최적 구간은 2~4일이고, 매출 합은 `3 + (-1) + 4 = 6`입니다. 두 번째 질의는 전체가 최적 구간입니다.

### 명세 확인

- 서로 다른 질의는 독립적입니다. 한 질의의 선택이 다음 질의에 영향을 주지 않습니다.
- 하나 이상의 날을 반드시 선택해야 합니다. 따라서 매출이 모두 음수여도 답은 음수입니다.
- `left`, `right`는 1번부터 시작하는 인덱스이며 양 끝을 모두 포함합니다.

### 연습용 채점 그룹

| 그룹 | 조건 | 의도 |
|---|---|---|
| 1 | `N,Q ≤ 1,000` | 구간별 카데인 알고리즘으로도 통과 |
| 2 | 질의 구간이 하나 | 전체 최대 부분합 처리 확인 |
| 3 | `N,Q = 100,000` | 세그먼트 트리 또는 동등한 질의 자료구조 필요 |

## Q2. 정답

```python
def solution(sales, queries):
    neg_inf = -10**30
    size = 1
    while size < len(sales):
        size *= 2

    # (구간합, 최대 접두합, 최대 접미합, 최대 부분합)
    tree = [(0, neg_inf, neg_inf, neg_inf) for _ in range(2 * size)]
    for index, value in enumerate(sales):
        tree[size + index] = (value, value, value, value)

    def merge(left_node, right_node):
        total = left_node[0] + right_node[0]
        prefix = max(left_node[1], left_node[0] + right_node[1])
        suffix = max(right_node[2], right_node[0] + left_node[2])
        best = max(left_node[3], right_node[3], left_node[2] + right_node[1])
        return total, prefix, suffix, best

    for index in range(size - 1, 0, -1):
        tree[index] = merge(tree[index * 2], tree[index * 2 + 1])

    answer = []
    for left, right in queries:
        left = left - 1 + size
        right = right - 1 + size
        left_part = right_part = None

        while left <= right:
            if left % 2 == 1:
                left_part = tree[left] if left_part is None else merge(left_part, tree[left])
                left += 1
            if right % 2 == 0:
                right_part = tree[right] if right_part is None else merge(tree[right], right_part)
                right -= 1
            left //= 2
            right //= 2

        node = left_part if right_part is None else right_part if left_part is None else merge(left_part, right_part)
        answer.append(node[3])
    return answer
```

## Q2. 해설

구간의 최대 부분합을 빠르게 합치려면 네 값이 필요합니다: 구간 전체 합, 맨 왼쪽에서 시작하는 최대 합, 맨 오른쪽에서 끝나는 최대 합, 구간 내부 최대 부분합입니다. 두 구간을 합칠 때 새 최대 부분합은 왼쪽 내부, 오른쪽 내부, 또는 `왼쪽 최대 접미합 + 오른쪽 최대 접두합` 중 하나입니다.

- 시간복잡도: 트리 구축 `O(N)`, 질의 하나당 `O(log N)`
- 핵심 반례: `sales=[-5,-2,-3]`, 질의 `[1,3]`의 정답은 빈 배열의 합 0이 아니라 `-2`입니다.

## Q3. 문제 — 제한 예산의 연속 구독

일별 이용료 `costs`와 예산 `budget`이 주어집니다. 합이 `budget` 이하인 연속 구간 중 길이가 가장 긴 구간의 길이를 return 하세요.

### 제한사항

- `1 ≤ len(costs) ≤ 300,000`
- `1 ≤ costs[i] ≤ 10^9`
- `1 ≤ budget ≤ 10^9`

### 입출력 예

| costs | budget | result |
|---|---:|---:|
| `[2,1,3,2,1]` | `6` | `3` |

합이 6 이하인 최대 길이 구간은 `[2,1,3]`, `[1,3,2]`, `[3,2,1]` 중 하나입니다.

### 명세 확인

- 빈 구간은 선택할 수 없습니다. 어떤 원소도 예산 이하가 아니라면 0을 return 합니다.
- 이용료는 모두 양수입니다. 이 조건이 있어야 투 포인터의 단조성이 성립합니다.
- 길이가 최대인 구간이 여러 개여도 길이만 return 하면 됩니다.

### 연습용 채점 그룹

| 그룹 | 조건 | 의도 |
|---|---|---|
| 1 | `N ≤ 2,000` | 이중 반복문 기준 풀이 검증 |
| 2 | 큰 양수 비용 포함 | 창을 여러 칸 연속으로 줄이는지 확인 |
| 3 | `N = 300,000` | 각 포인터가 한 번씩만 이동하는지 확인 |

## Q3. 정답

```python
def solution(costs, budget):
    left = 0
    current_sum = 0
    answer = 0

    for right, cost in enumerate(costs):
        current_sum += cost
        while current_sum > budget:
            current_sum -= costs[left]
            left += 1
        answer = max(answer, right - left + 1)

    return answer
```

## Q3. 해설

모든 이용료가 양수이므로 오른쪽 끝을 늘리면 구간 합은 커지고, 왼쪽 끝을 줄이면 구간 합은 작아집니다. 따라서 오른쪽 포인터는 한 번만 증가하고 왼쪽 포인터도 전체 과정에서 한 번만 증가합니다.

- 시간복잡도: `O(N)`
- 핵심 반례: `costs=[10,1,1]`, `budget=2`처럼 첫 원소가 예산보다 커도 이후 길이 2 구간을 찾아야 합니다.

## Q4. 문제 — 최소 서버 성능

작업량 배열 `works`를 한 대의 서버가 순서대로 처리합니다. 서버 성능이 `x`일 때 작업량 `work` 하나의 처리 시간은 `ceil(work / x)`분입니다.

모든 작업을 `limit`분 안에 끝낼 수 있는 최소 양의 정수 성능 `x`를 return 하세요. 답은 항상 존재합니다.

### 제한사항

- `1 ≤ len(works) ≤ 300,000`
- `1 ≤ works[i] ≤ 10^9`
- `len(works) ≤ limit ≤ 10^18`

### 입출력 예

| works | limit | result |
|---|---:|---:|
| `[9,7,5]` | `8` | `3` |

성능이 3이면 처리 시간은 각각 3분, 3분, 2분으로 총 8분입니다. 성능 2에서는 총 12분이므로 조건을 만족하지 못합니다.

### 명세 확인

- 작업은 병렬 처리되지 않습니다. 각 작업의 처리 시간을 모두 더합니다.
- 서버 성능은 양의 정수만 가능합니다.
- `limit`은 작업 개수 이상이므로 충분히 큰 성능을 선택하면 항상 처리할 수 있습니다.

### 연습용 채점 그룹

| 그룹 | 조건 | 의도 |
|---|---|---|
| 1 | 작업 수 1개 | 올림 나눗셈 경계 확인 |
| 2 | 작업량 최대 10,000 | 완전 탐색과 이분 탐색 비교 |
| 3 | 작업량 10^9, 제한 10^18 | 정수 범위와 성능 검증 |

## Q4. 정답

```python
def solution(works, limit):
    left = 1
    right = max(works)

    while left < right:
        mid = (left + right) // 2
        required_time = sum((work + mid - 1) // mid for work in works)

        if required_time <= limit:
            right = mid
        else:
            left = mid + 1

    return left
```

## Q4. 해설

성능 `x`가 가능하면 그보다 큰 성능도 항상 가능합니다. 반대로 `x`가 불가능하면 더 작은 성능도 불가능합니다. 이 단조성을 이용해 답의 범위를 이분 탐색합니다. 올림 나눗셈은 `(work + x - 1) // x`로 계산합니다.

- 시간복잡도: `O(N log max(works))`
- 핵심 반례: 처리 시간 합이 매우 커질 수 있으므로 Java/C++에서는 64비트 정수형을 사용해야 합니다.

### 정확성 근거

성능 `x`에서의 총 처리 시간을 `T(x)`라고 하면, `x`가 커질수록 각 작업의 `ceil(work / x)`는 증가하지 않으므로 `T(x)`도 증가하지 않습니다. 따라서 `T(x) ≤ limit`인 성능의 집합은 어떤 최솟값부터 시작하는 연속 구간입니다. 이분 탐색은 이 최솟값을 반환합니다.
